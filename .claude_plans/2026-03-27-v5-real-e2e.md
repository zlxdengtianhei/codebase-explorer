本次迭代的完成标准是**文件系统级验证**，不是 LLM Judge：

```
在 test_repos/flask/ 上执行完整工作流后，以下条件必须全部满足：

R1. test_repos/flask/.codebase-analysis/ 存在，包含 6 个 JSON 文件（01~06 + state.json）
R2. test_repos/flask/.codebase-docs/INDEX.md 存在且 >500 bytes
R3. test_repos/flask/.codebase-docs/ 下至少有 3 个子目录，每个含 OVERVIEW.md

## 2. 工作分块

### Block A: 修复 MCP 服务端实现（代码修改）

#### A1. 修复 `dep_count` 计算
- **文件**: `src/server.py` → `get_modules()` 函数
- **问题**: `dep_count` 对每个模块都是 0
- **修复**: 在构建模块摘要时，从 `02_dag.json` 计算跨模块边的数量
- **验证**: `pytest tests/test_graph.py -v` + 手动检查 `get_modules()` 返回值

#### A2. 修复 `get_dependency_graph(scope='project')` 返回模块级图
- **文件**: `src/server.py` → `get_dependency_graph()` 函数
- **问题**: scope='project' 返回文件级 DAG（441 nodes），应返回模块级聚合图（~10 nodes）
- **修复**: 当 scope='project' 时，将文件节点聚合到所属 feature cone，边权 = 跨模块边数之和
- **验证**: 返回的 node_count < 20

#### A3. 实现 `doc_operation` 的真实文件操作
- **文件**: `src/server.py` → `doc_operation()` 函数
- **当前状态**: 5 个 CRUD 操作全是 stub（返回 fake success）
- **修复范围**:
  - `move_detail`: 实际移动文件 + 更新 doc-index.json
  - `merge_modules`: 合并两个模块的文件到目标目录 + 更新 doc-index.json
  - `split_module`: 拆分模块目录 + 更新 doc-index.json
  - `update_index`: 重新生成 INDEX.md（从 doc-index.json + 各 OVERVIEW.md）
  - `reorder_modules`: 更新 doc-index.json 中的模块顺序
- **验证**: 每个操作前后检查文件系统状态变化

#### A4. 单元测试覆盖
- 为 A1-A3 的每个修复编写对应的 pytest 测试
- Guard: 所有现有测试继续通过

### Block B: 创建真实 E2E 验证脚本

#### B1. 编写 `scripts/verify_real_e2e.sh`
- 纯 bash，检查文件系统，不依赖 LLM
- 输入: test repo 路径（默认 `test_repos/flask`）
- 检查 R1-R10，输出 `PASS`/`FAIL` 和总分
- 退出码: 0=全部通过, 1=有失败

#### B2. 编写 E2E 运行脚本 `scripts/run_real_e2e.sh`
- 用 Claude Code 自调用机制执行完整工作流:
  1. 清理旧的 `.codebase-analysis/` 和 `.codebase-docs/`
  2. 启动子 Claude Code 实例，加载 codebase-explorer MCP + codebase-explorer Skill
  3. 子实例执行 `/codebase-explorer` 对 `test_repos/flask` 进行完整分析+文档生成
  4. 调用 `verify_real_e2e.sh` 验证结果
- 关键参数:
  ```bash
  env -u CLAUDECODE claude -p "..." \
    --dangerously-skip-permissions \
    --max-turns 50 \
    --output-format json \
    --no-session-persistence \
    --model sonnet \
    --setting-sources "user,project" \
    --strict-mcp-config \
    --mcp-config '<codebase-explorer MCP config>' \
    --allowedTools "Read,Edit,Write,Bash,Glob,Grep,Task,Skill,mcp__codebase-explorer" \
    > .cc_test_logs/real_e2e_result.json 2> .cc_test_logs/real_e2e_debug.log
  ```

### Block C: Autoresearch 循环

#### C1. 启动 Autoresearch
- **Goal**: 完整端到端文档生成流程在 test_repos/flask 上通过所有 R1-R10 检查
- **Metric**: `scripts/verify_real_e2e.sh test_repos/flask` 的通过数 X/10
- **Direction**: maximize
- **Verify**: `bash scripts/verify_real_e2e.sh test_repos/flask`
- **Guard**: `python -m pytest tests/ -x -q` (所有现有测试通过)

#### C2. 迭代策略
- 每次迭代只修改一个组件（原子修改）
- 修改后先跑 Guard（pytest），再跑 Verify（real E2E）
- 如果 Verify 分数下降 → `git checkout .` 回滚
- 记录每次迭代的分数变化到 `experiment_log.tsv`

## 5. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 子 Claude 实例执行 Skill 时 max-turns 不够 | 设 50 turns，flask 是小项目应该够 |
| MCP server 启动失败 | 先用 `--debug-file` 确认 MCP 连接正常 |
| doc_operation 实现改动破坏现有测试 | Guard 先行，每次改动后立即跑 pytest |
| 再次陷入"优化指标而非实际功能" | R1-R10 全部是文件系统检查，无法欺骗 |
| Autoresearch 的 Verify 步骤太慢（子 Claude 调用耗时长） | 先通过 pytest 确认逻辑正确，再跑完整 E2E |
