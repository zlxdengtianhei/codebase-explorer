# Core Format Engine

**Capability.** Implements the narrow-char formatting pipeline: detail::vformat_to fills a buffer from a format string and args, vformat returns strings, and printable-character checking plus scratch allocation support the engine.

Consult when changing core formatting behavior shared by all public APIs. Extension headers route their per-char-type work through this pipeline.

### `include/fmt/format-inl.h:vformat_to`

`FMT_FUNC void vformat_to(buffer<char>& buf, string_view fmt, format_args args, locale…` · [include/fmt/format-inl.h:L1468-L1475][f1]

Fills a buffer<char> by interpreting the format string with the given args and optional locale.

For exactly the two-character string "{}" it short-circuits: argument 0 is visited with a default_arg_formatter writing to the buffer. Otherwise parse_format_string drives a format_handler over the whole string, which resolves replacement fields, applies specs and locale, and writes all output through an appender onto the buffer. Malformed format strings raise errors through the parsing machinery (report_error path).

uses: [report_error](core-errors.md#u-4fe75221d1d1)

`FMT_FUNC auto vformat(string_view fmt, format_args args) -> std::string` · [include/fmt/format-inl.h:L1458-L1464][f1]

Formats args according to fmt into a freshly created memory_buffer via detail::vformat_to and returns the result as std::string.

The trivial "{}" fast path is intentionally not special-cased to keep binary size small. Exceptions from formatting propagate to the caller.

### `include/fmt/format-inl.h:is_printable`

`FMT_FUNC auto is_printable(uint32_t cp) -> bool` · [include/fmt/format-inl.h:L1827-L1985][f1]

Determines whether a Unicode code point is printable, using tables generated by support/printable.py.

The helper overload scans compact structures: a singleton list marks individual non-printable code points per high byte (checked by matching the low byte within per-upper-byte ranges), and a 'normal' run-length list toggles a printable/non-printable alternation as the signed code point is decremented by each run length, returning the final toggle state. The main function dispatches on cp: below 0x10000 uses singletons0/singletons0_lower/normal0; below 0x20000 uses singletons1/...; above that a chain of hard-coded range checks returns false for known non-printable gaps (0x2a6e0-0x2a700, 0x2b81e-0x2b820, 0x2ceae-0x2ceb0, 0x2ebe1-0x2ebf0, 0x2ee5e-0x2f800, 0x2fa1e-0x30000, 0x3134b-0x31350, 0x3347a-0xe0100, 0xe01f0-0x110000), and otherwise true for cp < 0x110000.

**Uncertainties.**

- Correctness of the generated tables cannot be verified from the source; the run-length decoding in the helper reads normal[++i] for two-byte lengths, so an odd table would misbehave silently.

### `allocate`

Allocates raw memory of the requested size via malloc.

If malloc returns null it throws std::bad_alloc instead of returning null, so the returned pointer is always valid.
