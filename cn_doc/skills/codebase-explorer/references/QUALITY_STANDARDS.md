## 1. 覆盖率标准

### 阈值：>= 80% 模块覆盖率

覆盖率衡量已检测模块中拥有对应文档的比例。

```
coverage = documented_modules / total_modules
```

| 覆盖率 | 等级   | 操作                               |
| ------ | ------ | ---------------------------------- |
| >= 95% | 优秀   | 无需操作                           |
| 80-94% | 合格   | 在最终报告中注明未覆盖的模块       |
| 60-79% | 不达标 | 必须在完成前为关键模块补充文档     |
| < 60%  | 不合格 | 分析不完整；继续分析或报告阻塞问题 |

### 什么算作"已文档化"

满足以下条件的模块视为已文档化：

1. 已通过 `submit_analysis` 提交分析结果
2. 至少为其生成了一个文档（OVERVIEW 或 DETAIL）
3. 文档包含：
   - 模块名称和描述
   - 至少列出一个公共接口
   - 至少记录一个依赖关系

### 可跳过文档的模块

- **深度 0 的模块**：太小，不需要单独文档；合并到父文档中。
  如果父文档的 OVERVIEW 包含关于它们的摘要段落，这些模块仍计为"已文档化"。
- **自动生成或供应商模块**：如果用户确认，可从覆盖率计算中排除。

## 2. 链接有效性标准

### 阈值：100% 链接有效性

生成文档中的每个超链接必须可以解析：

| 链接类型                    | 验证规则                         |
| --------------------------- | -------------------------------- |
| 内部文档链接 `[文本](路径)` | 文件必须在指定的相对路径存在     |
| 锚点链接 `[文本](#节)`      | 标题必须在目标文档中存在         |
| 交叉引用链接                | 目标文档必须在文档树中           |
| 父文档链接                  | 必须指向已存在的父文档           |
| 子文档链接                  | 必须指向已存在的子文档           |
| 源文件链接                  | 必须与代码库中的实际文件路径匹配 |

### 验证流程

```
对于每个生成的文档：
  1. 提取所有 Markdown 链接：[文本](url)
  2. 对于相对路径：
     - 相对于文档目录解析
     - 检查文件是否存在
  3. 对于锚点链接（#节）：
     - 解析目标文档的标题
     - 验证锚点与标题别名匹配
  4. 报告断开的链接，包含：
     - 源文档路径
     - 行号
     - 预期目标
     - 建议修复方案
```

### 常见链接错误

| 错误           | 原因                 | 修复方法                        |
| -------------- | -------------------- | ------------------------------- |
| 缺少父链接     | 父文档尚未生成       | 按正确顺序生成（自底向上）      |
| 子链接断开     | 子文档已合并到父文档 | 删除链接，改为内联摘要          |
| 路径中深度错误 | 路径计算错误         | 验证 `../` 数量与层级差是否匹配 |
| 找不到锚点     | 链接后标题发生了变化 | 重新生成链接文档                |

## 3. Token 预算合规性

### 阈值：>= 90% 的文档在预算内

满足以下条件的文档视为"在预算内"：

```
actual_tokens <= token_budget * 1.10  # 允许 10% 超出
```

| 合规率 | 等级   | 操作                       |
| ------ | ------ | -------------------------- |
| >= 95% | 优秀   | 无需操作                   |
| 90-94% | 合格   | 在报告中注明超预算文档     |
| 80-89% | 不达标 | 使用裁剪重新生成超预算文档 |
| < 80%  | 不合格 | 审查模板配置和预算分配     |

### 超预算恢复

如果文档超出预算：

1. 识别哪些内容部分消耗了最多 Token
2. 应用基于优先级的裁剪（参见 DOC_TEMPLATES.md 第 5 节）
3. 裁剪顺序：示例、内部辅助函数、边缘情况、
   实现说明、数据流图
4. 用相同的 `token_budget` 重新调用 `generate_doc`

### 预算不足评估

Token 使用量明显低于预算（< 50% 利用率）的文档可能表明：

- 缺少内容部分
- 分析深度不足
- 模块比预期简单（如果深度评估正确，则可接受）

检查预算不足的文档是否仍然包含其层级所需的所有部分。

## 4. 动态深度验证

### 深度决策合理性

在 `plan_doc_structure` 之后，验证深度分配是否合理：

| 模块特征             | 预期深度  | 标记条件        |
| -------------------- | --------- | --------------- |
| < 100 行，< 5 个函数 | 0（合并） | 深度 > 1        |
| 100-500 行           | 1         | 深度 > 2        |
| 500-2000 行          | 1-2       | 深度 > 3        |
| 2000-5000 行         | 2-3       | 深度 < 1 或 > 4 |
| 5000+ 行             | 3-5       | 深度 < 2        |
| 工具模块（任意大小） | 0-2       | 深度 > 2        |

### 拆分策略验证

| 代码风格            | 预期策略       | 标记条件                    |
| ------------------- | -------------- | --------------------------- |
| 2+ 个均衡子包       | SUBPACKAGE     | 选择了 CLASS 或 FILE        |
| OOP 为主（3+ 个类） | CLASS          | 选择了 FUNCTION_GROUP       |
| 函数式（少量类）    | FUNCTION_GROUP | 选择了 CLASS                |
| 混合内容            | HYBRID         | --                          |
| 扁平结构            | FILE           | 选择了 SUBPACKAGE（无子包） |

### 最小可文档化单元强制执行

对于低于以下阈值的单元，**不应**创建子文档：

| 指标          | 最小值 | 低于时的操作               |
| ------------- | ------ | -------------------------- |
| 代码行数      | 30     | 作为内联部分合并到父文档   |
| 函数数        | 2      | 合并到父文档               |
| 类数          | 1      | 合并到父文档（针对类拆分） |
| 估算 Token 数 | 200    | 作为摘要行合并到父文档     |

### 终止条件审计

树中的每个叶文档都应有一个有效的终止原因：

| 原因                         | 有效条件                       |
| ---------------------------- | ------------------------------ |
| `max_depth_reached`          | 当前深度等于配置的最大深度     |
| `below_min_lines`            | 代码行数低于配置的阈值         |
| `budget_exhausted`           | 剩余预算低于最小值             |
| `no_meaningful_split`        | 无法创建 2+ 个可文档化的子单元 |
| `utility_module_depth_limit` | 工具模块已达深度 2             |
| `single_unit_file`           | 单个文件，0-1 个类             |

## 5. 内容质量检查清单

### 层级 0（INDEX.md）

- [ ] 项目名称和描述存在
- [ ] 技术栈已列出
- [ ] 包含 Mermaid 架构图
- [ ] 所有模块已附描述列出
- [ ] 模块链接可解析到 OVERVIEW 文档
- [ ] 入口点已记录
- [ ] 指标表（文件数、函数数、类数、代码行数）
- [ ] 顶部有 doc-meta 注释
- [ ] Token 数在预算内

### 层级 1（OVERVIEW.md）

- [ ] 模块名称和描述
- [ ] 导航：指向父 INDEX.md 的链接
- [ ] 导航：指向子 DETAIL 文档的链接
- [ ] Mermaid 依赖图（显示导入关系）
- [ ] 列出导入依赖及链接
- [ ] 列出被引用方及链接
- [ ] 公共接口及其签名
- [ ] 组件表（如果深度 > 1）
- [ ] 文件列表（必要时截断至 15 个）
- [ ] 指标（file_count, function_count, class_count, complexity）
- [ ] 顶部有 doc-meta 注释
- [ ] Token 数在预算内

### 层级 2+（DETAIL.md）

- [ ] 组件名称和描述
- [ ] 面包屑导航链（从所有层级返回到 INDEX）
- [ ] Mermaid 内部结构图
- [ ] 包含方法表的类（公共方法）
- [ ] 函数及其签名和描述
- [ ] 调用关系（called_by, calls）
- [ ] 数据流图（深度 4+ 时可选）
- [ ] 子组件表（如有子节点）
- [ ] 列出源文件
- [ ] 顶部有 doc-meta 注释
- [ ] Token 数在预算内

## 6. 阶段门控标准

### 阶段一 -> 阶段二 门控

| 标准                                      | 是否必须 |
| ----------------------------------------- | -------- |
| `index_codebase` 返回 `status: "success"` | 是       |
| `project_id` 可用                         | 是       |
| 摘要统计信息已报告给用户                  | 是       |

### 阶段二 -> 阶段三 门控

| 标准                              | 是否必须 |
| --------------------------------- | -------- |
| `get_modules` 返回非空模块列表    | 是       |
| 用户已确认模块分组                | 是       |
| `create_analysis_plan` 已创建任务 | 是       |
| `plan_doc_structure` 已规划文档树 | 是       |

### 阶段三 -> 阶段四 门控

| 标准                                      | 是否必须 |
| ----------------------------------------- | -------- |
| 所有分析任务已完成或跳过                  | 是       |
| `get_analysis_status` 显示 0 个待处理任务 | 是       |
| 至少 80% 的模块有分析结果                 | 是       |

### 阶段四 -> 阶段五 门控

| 标准                    | 是否必须 |
| ----------------------- | -------- |
| 所有规划文档均已生成    | 是       |
| `doc-index.json` 已创建 | 是       |
| 文档已写入输出目录      | 是       |

### 阶段五 完成标准

| 标准                            | 是否必须 |
| ------------------------------- | -------- |
| 链接有效性：100%                | 是       |
| 模块覆盖率：>= 80%              | 是       |
| Token 合规率：>= 90%            | 是       |
| 每个 OVERVIEW 都有 Mermaid 图表 | 是       |
| 最终摘要已报告给用户            | 是       |
