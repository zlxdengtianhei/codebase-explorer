# SHA-512/256 hashing

**Capability.** SHA-512/256 with a compile-time backend dispatch (OpenSSL, wolfSSL, GnuTLS, bundled FIPS implementation) exposed through init/update/finish and a one-shot API, plus an HMAC dispatch table.

Use Curl_sha512_256it for one-shot hashing or the context API for streaming. The backend is selected at compile time; only the bundled implementation's internals (transform, context) are readable here.

### `lib-curl_sha512_256-backend-dispatch`

`group` · [lib/curl_sha512_256.c:L1-L110][f1]

Selects one SHA-512/256 backend at compile time in priority order OpenSSL, wolfSSL, GnuTLS, then a bundled FIPS 180-4 implementation.

OpenSSL is chosen only when not LibreSSL, or LibreSSL >= 0x3080000fL; on NetBSD it defines NEED_NETBSD_SHA512_256_WORKAROUND for versions with a known SHA-512/256 bug (before 9.4, 9.99.x, and 10.99.x before 10.99.11). wolfSSL is used unless WOLFSSL_NOSHA512_256 is defined; GnuTLS only when nettle/sha2.h defines SHA512_256_DIGEST_SIZE. If none qualify, HAS_SHA512_256_IMPLEMENTATION stays undefined and the local implementation compiles. The entire file is compiled out when CURL_DISABLE_DIGEST_AUTH or CURL_DISABLE_SHA512_256 is defined. The common init/update/finish signatures and Curl_sha512_256_ctx typedef form the backend-agnostic contract consumed by Curl_sha512_256it and Curl_HMAC_SHA512_256.

contract: [lib-curl_sha512_256-openssl-backend](r7-sha512-256.md#u-6df3988519ac), [lib-curl_sha512_256-wolfssl-backend](r7-sha512-256.md#u-d433cccd786a), [lib-curl_sha512_256-gnutls-backend](r7-sha512-256.md#u-8472b88e78cd), [lib-curl_sha512_256-local-implementation](r7-sha512-256.md#u-16e536934c94)

**Uncertainties.**

- USE_OPENSSL, USE_WOLFSSL and USE_GNUTLS are defined outside this file; only their consumption is observable here.

### `lib-curl_sha512_256-gnutls-backend`

`static CURLcode Curl_sha512_256_init(void *context)` · [lib/curl_sha512_256.c:L239-L249][f1]

GnuTLS/nettle-backed SHA-512/256, compiled when USE_GNUTLS_SHA512_256 is defined; sizes come from nettle macros and the context is a struct sha512_256_ctx by value.

init debug-asserts that the header digest length matches the nettle digest size, calls sha512_256_init, and always returns CURLE_OK because nettle's init returns void. update debug-asserts data is non-NULL unless length is 0, delegates to sha512_256_update, and always returns CURLE_OK. finish calls sha512_256_digest in a two-argument form when NETTLE_VERSION_MAJOR >= 4, otherwise the legacy form passing the digest size explicitly, and always returns CURLE_OK; underlying failures cannot be reported through this signature.

### `lib-curl_sha512_256-openssl-backend`

`static CURLcode Curl_sha512_256_init(void *context)` · [lib/curl_sha512_256.c:L111-L131][f1]

OpenSSL-backed SHA-512/256, compiled when USE_OPENSSL_SHA512_256 is defined.

CURL_SHA512_256_BLOCK_SIZE is 128 and DIGEST_SIZE aliases the header macro; Curl_sha512_256_ctx is an EVP_MD_CTX pointer, so callers pass a pointer-to-pointer as context. init allocates with EVP_MD_CTX_new, returning CURLE_OUT_OF_MEMORY if allocation fails; if EVP_DigestInit_ex fails it frees the context and returns CURLE_FAILED_INIT; on success it debug-asserts digest and block sizes match the macros and returns CURLE_OK. update returns CURLE_BAD_FUNCTION_ARGUMENT when EVP_DigestUpdate fails, else CURLE_OK. finish runs EVP_DigestFinal_ex; under NEED_NETBSD_SHA512_256_WORKAROUND it finalizes into a doubled-size temporary buffer, copies only the first DIGEST_SIZE bytes into digest, and zeroes the temporary; both paths free the EVP_MD_CTX and null the caller's pointer, so finish is one-shot and the context cannot be reused.

group: [lib-curl_sha512_256-backend-dispatch](r7-sha512-256.md#u-57e69fc65d16)

**Uncertainties.**

- Whether the NetBSD workaround fully avoids the cited platform bug depends on the NetBSD crypto library, not this code.

### `lib-curl_sha512_256-wolfssl-backend`

`static CURLcode Curl_sha512_256_init(void *ctx)` · [lib/curl_sha512_256.c:L195-L200][f1]

wolfSSL-backed SHA-512/256, compiled when USE_WOLFSSL_SHA512_256 is defined; sizes come from wolfSSL macros and the context is a struct wc_Sha512 by value.

init returns CURLE_FAILED_INIT if wc_InitSha512_256 reports failure, else CURLE_OK. update loops because wolfSSL takes a word32 length: it feeds at most UINT_MAX bytes per wc_Sha512_256Update call, advancing data and shrinking length until exhausted; any sub-call failure aborts with CURLE_BAD_FUNCTION_ARGUMENT mid-stream, leaving partially hashed data in the context. finish wraps wc_Sha512_256Final and returns CURLE_BAD_FUNCTION_ARGUMENT on failure; unlike the OpenSSL path it neither frees nor resets the context.

group: [lib-curl_sha512_256-backend-dispatch](r7-sha512-256.md#u-57e69fc65d16)

**Uncertainties.**

- Whether wc_Sha512_256Final leaves the context reusable is decided by wolfSSL, not visible here.

### `Curl_rotr64`

`static CURL_FORCEINLINE uint64_t Curl_rotr64(uint64_t value, unsigned int bits)` · [lib/curl_sha512_256.c:L348-L355][f1]

Rotates a 64-bit value right by a variable bit count for the local SHA-512/256 transform.

It reduces bits modulo 64; when the reduced count is 0 it returns the value unchanged, avoiding the undefined shift by 64 the generic expression would perform. Otherwise it returns (value >> bits) | (value << (64 - bits)). Declared CURL_FORCEINLINE so each argument is evaluated once, unlike a macro that could duplicate argument computations.

### `Curl_sha512_256_finish`

`static CURLcode Curl_sha512_256_finish(unsigned char *digest, void *context)` · [lib/curl_sha512_256.c:L711-L781][f1]

Finalizes the bundled context into a 32-byte big-endian digest and always returns CURLE_OK.

It captures the total bit count (count << 3), appends the 0x80 padding byte after the buffered bytes, and if fewer than 16 bytes remain in the current block it zero-pads, transforms that block, and starts a fresh one. It then zero-fills up to the 16-byte length field, writes count_bits_hi and the low bit count as two big-endian 64-bit words at the block tail, and transforms the final block. The leftmost four hash words are stored big-endian into digest, and the whole context is memset to zero to erase sensitive state, so the context is unusable afterwards.

**Notes.**

- failure: No failure path exists: padding, transforms and digest writes cannot fail, and CURLE_OK is returned unconditionally.

calls: [Curl_sha512_256_transform](r7-sha512-256.md#u-6562086c1a33)

### `Curl_sha512_256_init`

`static CURLcode Curl_sha512_256_init(void *context)` · [lib/curl_sha512_256.c:L442-L468][f1]

Initializes the bundled SHA-512/256 context: loads the eight FIPS 180-4 section 5.3.6.2 IV constants into H, zeroes count and count_bits_hi, and returns CURLE_OK unconditionally.

Debug asserts check that the header digest length equals this file's digest size and that uint64_t is exactly 8 bytes; both vanish in release builds. No allocation occurs, so this init cannot fail.

**Notes.**

- side_effect: Overwrites H and the counters without clearing the 128-byte buffer; stale buffer bytes remain until overwritten by update or finish padding.

uses: [Curl_sha512_256ctx](r7-sha512-256.md#u-7e766603955e)

### `Curl_sha512_256_transform`

`static void Curl_sha512_256_transform(uint64_t H[SHA512_256_HASH_SIZE_WORDS], const v…` · [lib/curl_sha512_256.c:L476-L629][f1]

Core SHA-512/256 compression: consumes one full 128-byte block and mixes it into the eight hash words, returning nothing.

It copies H into working variables a..h, reads the first 16 big-endian words directly from the input into a 16-word cyclic W buffer, and runs 80 rounds via SHA2STEP64RV (an unrolled variant updating variables in place then rotating them), using the fixed K constant table for round keys; rounds 16..79 generate W values from earlier W entries with the sig0/sig1 schedule macros. Finally each working variable is added back into H in place. The input must be exactly CURL_SHA512_256_BLOCK_SIZE bytes; callers guarantee this. Ch/Maj/Sigma macros implement the FIPS 180-4 formulas; Curl_rotr64 keeps shifts defined for all bit counts.

calls: [Curl_rotr64](r7-sha512-256.md#u-3b4581825a87)

**Uncertainties.**

- The Ch/Maj macro comments attribute formulas to sections 4.8/4.9 while calling them FIPS 180-4 formulae; the source reference could not be checked here.

### `Curl_sha512_256_update`

`static CURLcode Curl_sha512_256_update(void *context, const unsigned char *data, size…` · [lib/curl_sha512_256.c:L639-L690][f1]

Feeds an arbitrary-length byte range into the bundled context, always returning CURLE_OK.

A zero length short-circuits with no effect. It computes bytes_have from count modulo the 128-byte block size, then advances count by length, bumping count_bits_hi when the addition wraps and again for each full 2^61 bytes before masking count to 61 bits. If the buffer holds partial data and the new data fills it, the remainder is appended and a full block is transformed; then every whole block of remaining data is transformed directly from the caller's buffer without copying; any final partial block is memcpy'd into the context buffer at the current offset. data may be NULL only when length is 0 (debug-asserted).

**Notes.**

- side_effect: Mutates the caller's local data/length copies only; the caller's original buffer is read, never written.

calls: [Curl_sha512_256_transform](r7-sha512-256.md#u-6562086c1a33)

**Uncertainties.**

- The count_bits_hi update assumes total input never reaches 2^64 bytes of low count without wrap handling beyond the single observed carry branch; behavior at extreme sizes rests on that branch alone.

### `Curl_sha512_256it`

`CURLcode Curl_sha512_256it(unsigned char *output, const unsigned char *input, size_t …` · [lib/curl_sha512_256.c:L792-L810][f1]

One-shot SHA-512/256 of a byte range using whichever backend was selected, writing the 32-byte digest to output.

It initializes a stack context, returning the backend's init error directly (for OpenSSL this can be CURLE_OUT_OF_MEMORY or CURLE_FAILED_INIT) without touching output. If update fails it still calls finish to release/tear down the context, discards finish's result, and propagates the update error. On success it returns finish's result, which for the local, GnuTLS and wolfSSL paths is always CURLE_OK.

calls: [Curl_sha512_256_init](r7-sha512-256.md#u-c409aaac306b), [Curl_sha512_256_update](r7-sha512-256.md#u-f1677e368810), [Curl_sha512_256_finish](r7-sha512-256.md#u-f5dcfa2b775d)

**Uncertainties.**

- Because init/update/finish are static and one definition set is compiled, the calls bind to whichever backend branch is active; the exact callee depends on build configuration.

### `Curl_sha512_256ctx`

`struct Curl_sha512_256ctx` · [lib/curl_sha512_256.c:L407-L429][f1]

Defines the bundled-implementation context: eight 64-bit intermediate hash words (H), a 16-word aligned 128-byte input buffer, a byte counter (count, top 3 bits kept clear as a wrap guard), and count_bits_hi holding the high part of the total bit count.

A typedef aliases this struct as Curl_sha512_256_ctx for the local backend.
